- Others, namely Lindley, have studied "feature-local" translation. See for example this explanation:
> We use macro-local as a synonym for macro-expressibility as originally formulated by Felleisen [13]. A macro-local translation must be a homomorphism on constructs not in the feature, and translations on feature constructs must be specified by a fixed syntactic context, parameterized only by the translations of the subterms. However, macro-locality does not account for translations that carry extra parameters, whose use violates the fixed-context restriction, even when such translations do not require rewriting the entire program.
> We specify a weaker sense, feature-local, which also requires that the translation is a homo-
> morphism over constructs not in the feature, but which places no restriction on how features are
> translated. This sense is alluded to by e.g. Kawahara and Kameyama [23], who write that given a
> translation “for a primitive 𝑋 in a language 𝐿 ... we can implement 𝑋 using the translation without 0
> changing any other primitives in 𝐿0,” and by Lindley [29], who writes that “a local encoding permits only those parts of the program that manipulate the feature in question to be rewritten.” Concretely:
> • CPS translations [10, 44] and state-passing translations [50] are not feature-local (and so not macro-local) since since every computation in the language needs to be rewritten to thread through a continuation or state value, respectively.
> • A translation from named variables to de Bruijn indices [11] is feature-local but not macro- local. Translating variables requires “non-local” information about any surrounding binders, but unrelated features (e.g. application, products if we add them, etc.) are unaffected.
> • Translating let 𝑥 = 𝑀 in 𝑁 into (𝜆𝑥 .𝑁 ) 𝑀 [13] is macro-local (and so feature-local).
